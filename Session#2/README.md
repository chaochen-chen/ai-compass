# README — 薪資文件維護指南

這個資料夾用來追蹤不同公司的薪資福利，方便換工作/收到 offer 時快速比較。

## 檔案說明

| 檔案 | 用途 |
|---|---|
| `COMPENSATION.md` | 主文件，已填入 TSMC / Google / Nvidia 的資料 |
| `TEMPLATE.md` | 空白模板，新增公司時複製這份 |
| `README.md` | 維護流程 |

---

## 如何新增一間公司

1. 打開 `COMPENSATION.md`，複製整個 `## [公司名稱]` 到 `---` 的區塊
2. 貼到 `TEMPLATE.md` 的最後（新公司區塊之前）
3. 依下方「查資料流程」填入數字
4. 回到主文件最上方的**總覽表**，新增一列
5. 在該公司區塊底部的「附註」填上資料來源與日期

## 如何更新既有公司的資料

1. 找到該公司的區塊
2. 只更新有變動的欄位（通常是 Bonus、Total Comp、資料日期）
3. 如果新數字跟舊數字差異大，**保留一行簡短說明為什麼變了**（例如：「2026-08 起因AI需求獲利大增，分紅較原估上修」），方便之後回顧判斷是雜訊還是真趨勢
4. 同步更新總覽表對應的列

## 查資料流程（建議順序）

1. **公司官方揭露** — 最可信。校園徵才公告、證交所「員工福利政策及權益揭露」、永續報告書、10-K/年報。適合查：起薪、整體薪酬費用、福利制度。
2. **Levels.fyi** — 適合查：跨公司 level 對照、base/stock/bonus 拆解。⚠️ 見下方「踩過的坑」，不要照單全收。
3. **Dcard / PTT / Threads 討論串** — 適合查：最新「開獎文」（分紅公布當下的即時分享）、真實員工心得、內部用語對照。⚠️ 個案不代表平均，且容易高薪者才會分享。
4. **財經新聞** — 適合查：公司整體獲利/分紅池變化的官方數字佐證（例如分紅年增幅度），比自主申報數據更可信。

**原則：至少交叉比對 2 個來源再下數字，尤其是會直接拿去比較 offer 的關鍵數字。**

## 踩過的坑（更新資料時特別小心）

這些是之前整理時真的犯過的錯，下次更新時對照檢查：

- **⚠️ Base salary ≠ Total comp**：Levels.fyi 某些頁面幣別標示會混淆（例如明明是 NT$ 卻顯示 $），曾經誤把總薪酬數字當成本薪填入，導致 base 數字灌水快一倍。**每次填入 base 數字，都反推「月薪 x 幾個月」是否合理，並和公司官方揭露的起薪對照。**
- **⚠️ 固定薪 vs 變動薪要分開寫**：像 TSMC 這種分紅占比極高的公司，"base" 和 "total comp" 中間可能差 2-3 倍，混在一起寫容易誤導比較。
- **⚠️ 股票補貼方向要寫清楚**：「員工認股 85%」這種寫法容易讓人誤解成公司出 85%，實際可能是「公司補貼 15%、員工自己出 85% 價金」。動筆前先確認補貼方向。
- **⚠️ 分紅/股票相關數字很快過時**：尤其台積電這類分紅隨獲利大幅波動的公司，半年前的數字可能已經明顯低估或高估，**務必標註資料日期**，舊數字不要不加註明就沿用。
- **⚠️ 單一 Dcard 開獎文不代表平均**：願意曬分紅的通常是拿比較多的人，容易讓人高估平均水準；盡量找官方統計的「平均值/中位數」搭配個案參考。

---

## 建議更新頻率

- **快變動公司**（分紅占比高、股價連動強，如 TSMC / Nvidia）：至少每季檢查一次，尤其財報公布後
- **相對穩定公司**（base 為主、分紅結構固定，如多數傳產/外商）：每半年到一年檢查一次即可
- **正在準備面試/談 offer 的公司**：隨時更新，並優先採用最新的一手資料（官方 offer、直接詢問 HR）
